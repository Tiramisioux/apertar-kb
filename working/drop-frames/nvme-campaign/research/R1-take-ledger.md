## 0. Conventions

- **Status words are the KB's own** (confirmed / measured / probable / unconfirmed) and are carried without upgrade. Where
  a source gives a number without a label it is marked `(journal)` when it comes straight from Core's journal lines
  (the KB calls these "measured: numbers are real, the reading is not yet agreed", `night-2026-11-01.md:4-5`) or
  `(unlabelled)`. My own arithmetic or reading is marked **R1 derived** / **R1 inference** and is never a KB claim.
- **Counters** (`README.md:229-240`, confirmed from source): `dropped_gap_estimate` = `drop[capture-gap]` = libcamera
  delivered no frame for a period (the CFE skipped; lost *before* Core's queue); `dropped_queue_full` = `drop[queue-full]`
  = the 12-frame (24 for compressed) write queue was full (the disk fell behind); `drop[copy-slot]`; `drop[requeue-failed]`.
  `takes.sh missing` counts holes in the DNG numbering and **cannot see capture gaps** when the numbering counts written
  frames (`README.md:48`, A2 showed `missing=0` with 1,491 gaps; `hardware-log.md:770-773`). "Lost" in the 2026-11
  tables = `dropped_gap_estimate` unless a row says otherwise (`takes-2026-11-01.md:8`, "Lost at capture").
- **Abbreviations in the ledger.** hl = `lessons/hardware-log.md`; t1101 = `working/drop-frames/takes-2026-11-01.md`
  (take #k is at line 9+k); night = `working/drop-frames/night-2026-11-01.md`; tn = `tests-2026-11/transcript-numbers-2026-11-01.md`;
  pr = `tests-2026-11/preregistration.md`; f02/f03/f04 = `tests-2026-11/findings-2026-11-0{2,3,4}.md`; e4 =
  `tests-2026-11/findings-evening4-supervised-2026-11-04.md`; obs = `tests-2026-11/observations-2026-11-04.md`; tk =
  `tests-2026-11/takes.md`; rec = `working/drop-frames/recipe.md`; RM = `working/drop-frames/README.md`.
  Mode: HDR16 = 3840x2160 Clear HDR 16-bit (stream 3840x2200); SDR12 = 3840x2160 SDR 12-bit. Comp: U = uncompressed cDNG
  (`none`), LJ = lossless JPEG, LY = lossy DNG. Lost: `gap` = `dropped_gap_estimate`, `qf` = `dropped_queue_full`, `miss`
  = `takes.sh` missing / holes. DN = `APERTAR_DNG_DONTNEED` page-cache mode; **writer\*** = the per-frame
  `posix_fadvise(DONTNEED)` that is hard-coded in every build before `adac040` (the fork's old default and upstream's;
  `night:16-25`, `:304`, probable for builds where no one measured it). WB/sync = per-DNG `sync_file_range` hint /
  `APERTAR_MEDIA_SYNC_MS`. RB = raw camera buffers. Buf = `[storage] buffer` frames|ram. TDN: **on†** = the shipping
  tuning `defaults-pisp/imx585_clearHDR.json`, whose `tdn` block was confirmed by grep on 2026-11-03
  (`tier0-2026-11-03.md:15`); every HDR16 take on the automatic tuning ran with it; SDR takes load `imx585.json`, TDN state
  not stated (n/s). FE = libcamera `num_cfe_config_queue`: 2 is libcamera's default (`pr:598-600`) and applies to every
  take before 2026-11-04 evening 4. PL = frame-rate phase lock (`fps_phase_lock`, default off; on only in C0103 and the
  22:05-22:15 meter run of 2026-10-26, `hl:274`). n/s = not stated in the sources.
- Drive throughout: Corsair MP600 Mini 1 TB (firmware ERFM11.1), 932 GB exFAT, 128 KB clusters, `rw,noatime`, no
  `discard`, `/media/RAW`, PCIe Gen 3 x1 except where a row says Gen 2 (`hl:701-704`, `:306-311`). A second card exists:
  the owner's Crucial P310 (serial 25184FF10656), which was in the slot by mistake for two void takes on 2026-11-03
  (`f03:42-43`, `pr:263-264`). No trim of any kind existed before 2026-10-30 (`hl:701-734`); Core trims at mount and
  after deletes >= 1 GiB from the first `drop-frames` build (2026-10-31 22:26, `hl:813-825`).
- Bytes per frame (for the fill arithmetic): HDR16 U 16,896,000 B (`hl:146`, `f02:10`); HDR16 Log 12,451,344 B

Each item names the rows and the KB's label.

1. **Uptime / process age / position in a Core process.** Boot 1 of 2026-11-01 drifted from ~7 % (19:09) to 11-18 % (22:00-22:20)
   with Core, UI and card fresh (rows 77, 135-139; RM:203-206, labelled probable at the time); the inspection later found the
   drift "not supported" as an uptime effect (a step at 21:03, night:303). Under `writer` after the 22:27 reboot: 1 -> 34 -> 153 -> 71
   lost at uptime 1 -> 13 min (rows 143-146). B1 tested position: writer P1 clean / P2 losing was **not reproduced** (writer P1

   second take of a Core process is not interchangeable with the first.
2. **Instrumentation cost.** Every TDN-on 3-min unit of evening 3 (58 + 39, 115 + 116 lost, rows 192-193, 200-201) ran with the
