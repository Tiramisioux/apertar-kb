# R6 — Domain research: Linux exFAT internals, NVMe host memory buffer, trim, bandwidth, writeback, libcamera capture gaps

First load the web tools: call ToolSearch with query 'select:WebSearch,WebFetch'. Use WebSearch (mode 'standard', then 'extended' when thin) and WebFetch for primary sources (kernel source on git.kernel.org or elixir.bootlin.com, kernel docs, Raspberry Pi forums and docs, Corsair spec pages, reviews with sustained-write charts). Cite URLs.
Topics:
(a) Linux exfat driver (fs/exfat, kernel 6.12) write path: cluster allocation (exfat_alloc_cluster, exfat_ent_set, exfat_chain_cont_cluster, exfat_set_bitmap), when a file's FAT chain is written versus the NoFatChain flag (contiguous files), whether these metadata writes go through buffer heads synchronously (sync_dirty_buffer / __bread_gfp / __wait_on_buffer), the 'dirsync' default and the 'discard' mount option (what it does; online discard per cluster free), exfat_write_inode behaviour and when it runs, free-space fragmentation after many deletes and the allocation hint (clu_srch_ptr), directory lookup cost in a directory with 15000 to 25000 files (exfat_lookup linear scan? exfat_find; 32-byte entry sets, 3 entries per file: a 15000-file directory is about 1.4 MB of entries) and directory growth when files are created one per frame; cluster size effects (128 KB versus 1 MB: allocations per 16.9 MB file; bitmap writes). Also the exfat 'keep_last_dots', 'errors=', 'iocharset', 'zero_size_dir' options and anything about 'exfat_free_cluster' cost on delete (a 15000-file delete at 128 KB clusters).
(b) NVMe Host Memory Buffer (HMB) and the module parameter nvme.max_host_mem_size_mb=0: what the HMB is, what a DRAM-less drive uses it for (FTL mapping cache), the effect of refusing it on sustained write and on garbage collection, whether the Corsair MP600 Mini (1 TB, Phison E21T? check the controller and whether it is DRAM-less, pSLC cache size and post-cache TLC write speed), and why Raspberry Pi 5 / CM5 users set max_host_mem_size_mb=0 (known Pi 5 NVMe issues: controller resets, CSTS=0xffffffff, PCIe link drops); whether a smaller non-zero value works (e.g. 8, 16, 32 MiB), and whether Raspberry Pi's kernel changed the default.
(c) Raspberry Pi OS: is fstrim.timer enabled by default (weekly), does it cover a mounted /media/RAW; periodic trim versus online discard recommendations; exFAT fstrim support in the kernel driver (since which version).
(d) Pi 5 PCIe Gen 3 x1 practical throughput for NVMe (measured numbers), and the sustained (post-SLC-cache) write speed of the MP600 Mini 1 TB or the same controller family; also Samsung T7 USB 3.2 Gen 2 on the Pi 5 (UAS, about 400 MB/s?). State what MB/s a 4K 16-bit 25 fps uncompressed take (about 420 MB/s), a Log-12 take (about 310 MB/s), a 4K 12-bit 50 fps uncompressed take (about 620 MB/s) and a 4K 12-bit 60 fps take (about 745 MB/s) each need, and which drive/link can hold which for 10 minutes.
(e) sync_file_range(SYNC_FILE_RANGE_WRITE) semantics and interaction with balance_dirty_pages, vm.dirty_bytes/dirty_background_bytes, dirty_writeback_centisecs; how initiating writeback per file keeps the dirty set small and why a large dirty set can stall unrelated threads (direct reclaim on allocation, CMA allocations, writeback throttling landing on any thread that dirties pages). Also posix_fadvise(POSIX_FADV_DONTNEED) and SEQUENTIAL semantics on Linux.
(f) libcamera / Raspberry Pi CFE and PiSP: what happens when a request is not requeued in time (does the CFE drop the frame; is there a 'frame dropped' log; how many buffers the pipeline handler wants); FrameDurationLimits behaviour; the single CameraManager thread; known Pi 5 limits at 4K 50/60 fps raw on a single camera.
(g) USB SSD specifics: UAS versus usb-storage, write cache, the usb-storage.quirks option, max_sectors_kb, and known Pi 5 USB 3 bandwidth limits.
