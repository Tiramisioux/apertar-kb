## 2. Lens 3 — kernel mechanism (v6.12; rpi-6.12.y identical for the DONTNEED block)

### 2.1 What step 4 does to a 16.6 MB file whose ~4050 pages are all dirty (confirmed from source; timings probable)

| Step | Source | Effect here |
| --- | --- | --- |
| `len == 0` → `endbyte = LLONG_MAX` | mm/fadvise.c:72-74 | whole file |
| `__filemap_fdatawrite_range(mapping, 0, LLONG_MAX, WB_SYNC_NONE)` | mm/fadvise.c:113-115 → mm/filemap.c:421-431 (`nr_to_write = LONG_MAX`) → filemap.c:388-398 (`mapping_tagged(DIRTY)` true → `do_writepages`) → mm/page-writeback.c:2672-2683 → `exfat_writepages` fs/exfat/inode.c:405-411 → `mpage_writepages` fs/mpage.c:665-668 | every dirty folio is locked (page-writeback.c:2496 `folio_lock`, blocking, not trylock), passes `folio_prepare_writeback` (2433-2462: skipped only if not dirty or already under writeback), `folio_clear_dirty_for_io`, `folio_start_writeback` + unlock (mpage.c:619-620), DIRTY tag cleared / WRITEBACK tag set (page-writeback.c:3135, 3151-3152), bios of up to `BIO_MAX_VECS` (mpage.c:596; 256 × 4 KiB = 1 MiB) submitted under a plug. exFAT allocated the clusters at `write()` time (`block_write_begin(exfat_get_block)` inode.c:425-434; `exfat_map_cluster` → `exfat_alloc_cluster` inode.c:126, 200), so no allocation happens here. Result: **all pages of the file are under writeback, none DIRTY-tagged, when the call returns.** |
| `lru_add_drain()` (local CPU) | fadvise.c:156, mm/swap.c:726 | cheap |
| `mapping_try_invalidate(..., &nr_failed)` | fadvise.c:158 → mm/truncate.c:472-506 → `mapping_evict_folio` truncate.c:263-277: `if (folio_test_dirty(folio) \|\| folio_test_writeback(folio)) return 0;` | every folio still under writeback fails; each failure calls `deactivate_file_folio` (truncate.c:503 → swap.c:685-691) and `nr_failed++` (truncate.c:506) |
| `if (nr_failed) { lru_add_drain_all(); invalidate_mapping_pages(); }` | fadvise.c:166-168; swap.c:880-885 → `__lru_add_drain_all(false)` swap.c:789-878; truncate.c:535-538 (= `mapping_try_invalidate(..., NULL)`) | one global drain per DNG; second walk evicts only folios whose I/O completed meanwhile |

Timing (probable): 16.6 MB at the measured ~730 MB/s direct (HL:69) takes ~20 ms to land; two xarray walks over ~4050 entries plus the drain take well under that, so on nearly every frame `nr_failed ≫ 0` and `lru_add_drain_all` runs, and nearly all folios stay cached. **H3's mechanism statements are confirmed.**

### 2.2 What `lru_add_drain_all` costs (confirmed structure; magnitude probable)

- `__lru_add_drain_all`: `mutex_lock` (serialises concurrent writers), generation check `this_gen != lru_drain_gen` → skip entirely if another drain was scheduled since (swap.c:835), then `for_each_online_cpu: if (cpu_needs_drain(cpu)) queue_work_on(cpu, mm_percpu_wq, ...)` (swap.c:866-868) and `flush_work` on each queued CPU (swap.c:874). `mm_percpu_wq` is a normal-priority `WQ_MEM_RECLAIM` queue (mm/vmstat.c:2170-2176).
- `cpu_needs_drain` (swap.c:767-779) is true when any of six per-CPU folio batches (`PAGEVEC_SIZE` 31, include/linux/pagevec.h:15; drained automatically when full, swap.c:224-226) is non-empty, or a mlock batch, or the CPU's buffer-head LRU (`has_bh_in_lru`, fs/buffer.c:1521; 16 slots, :1293) is non-empty.
- So **"a drain on every CPU" is conditional, not unconditional**: a CPU is queued only if it has touched a buffer head (any exFAT metadata read) or holds a partial LRU batch since its last drain. On this workload (copy worker allocating 16.6 MB vectors, writers reading FAT/bitmap/directory buffer heads) that is practically every active CPU — probable, not measured. Cost on the calling writer: one mutex + flush of up to 3 remote kworkers (4-core Pi), bounded by CFS scheduling latency (no SCHED_FIFO thread in Core per H15); typically sub-ms, "tens of ms" only in the RT cases quoted by R6 e5. Cost on the CPU running libcamera's thread: a kworker runs for microseconds (drain ≤ 6 × 31 folios + 16 bh). **Identical in A0, A1 and A2**, so it cannot discriminate A1 from A2 — which is H3's point, not a contradiction of it.

### 2.3 Why step 7 is redundant, and what could make it non-redundant (confirmed from source)

- `sync_file_range(fd, 0, 0, SYNC_FILE_RANGE_WRITE)`: `nbytes == 0 → endbyte = LLONG_MAX` (fs/sync.c:266-267); WRITE alone → `__filemap_fdatawrite_range(mapping, 0, LLONG_MAX, WB_SYNC_NONE)` (sync.c:285-293) — **the same function with the same arguments as step 4**. The documented semantics: "initiate writeout of all those dirty pages in the range which are not presently under writeback" (sync.c:316); "Not suitable for data integrity operations" (sync.c:330).
- After step 4 no folio of the file carries the DIRTY tag (page-writeback.c:3151-3152), so step 7 returns 0 at `filemap_fdatawrite_wbc`'s `!mapping_tagged(mapping, PAGECACHE_TAG_DIRTY)` check (filemap.c:393-394) **before `do_writepages`**: no bio, no wbc attach. It is a tag probe.
- Paths that could re-dirty pages between steps 4 and 7, checked and excluded:
  - another writer to the same file — none: unique path per frame, same thread, all writes precede step 4 (§1.1);
  - `close()` — `exfat_file_operations` has **no `.release`** (fs/exfat/file.c:664-676); the inode's own metadata (size, clusters) is dirty in the *bdev* mapping via `mark_inode_dirty` (inode.c:456, 462), not in the file's page cache, and `sync_file_range` touches only `file->f_mapping` (sync.c:283, 292);
  - pages skipped by step 4 — `writeback_get_folio` uses a blocking `folio_lock` (page-writeback.c:2496), so nothing is skipped for lock contention; `WB_SYNC_NONE` skips only folios already under writeback (2452-2454), which are not dirty-tagged anyway;
  - `-ENOMEM` from `do_writepages` — retried only for `WB_SYNC_ALL` (page-writeback.c:2688-2694, not re-read in detail; R3 agrees); with WB_SYNC_NONE a failure would leave pages dirty and step 7 could pick them up — but then the A0/A1 "peak dirty 3-11 MB" would not hold and no ENOMEM has ever been logged; negligible;
  - the lossless `pwrite` header — written before DONTNEED (CE:1762-1769).
  **Conclusion: no mechanism makes step 7 initiate I/O. Confirmed.**
- What step 7 does cost (and A2 removed): an `open` by path = `exfat_lookup` → `exfat_find_dir_entry`, a linear walk of the clip directory's cluster chain with a resume hint (fs/exfat/dir.c:1003-1038, hint :1013-1027, name-hash compare :1080-1089; 15 000 files × 3 entries × 32 B ≈ 1.4 MB of directory by the end of a 10-min take), the tag probe, a `close`. So **A2 removed three syscalls, one of them an O(N) directory scan — a cost, not a writeback mechanism.** Correction to H3's "one redundant syscall".
- "The pages are not freed": correction — DONTNEED frees those folios whose I/O completed before its second walk (few); the rest are deactivated with `PG_reclaim` (swap.c:556-580) and rotate to the inactive tail at `folio_end_writeback` (mm/filemap.c:1611-1624 → swap.c:262), so later reclaim takes them first. Page cache grows at ≈ 415 MB/s (25 × 16.6 MB) until the low watermark, then kswapd reclaims clean pages continuously — the same in all three runs (probable; the A0/A1 "peak dirty" figures, HL:745/763, are consistent with this and inconsistent with "kernel writeback only", which would let dirty memory climb toward `dirty_background` before the flusher starts).
