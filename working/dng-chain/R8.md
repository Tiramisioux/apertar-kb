Core reads no PISP_COMP1 for Clear HDR (16-bit unpacked is what libcamera-apertar forces; kb `q7-cinemate.md:148`). The COMP1 stream is lossy ("steps of 16 codes or more" in the 16-bit domain, hardware-log `:861`); Core's "uncompressed" SDR DNGs therefore carry COMP1-decoded samples, not bit-exact sensor codes (probable: follows from the format; the decoder is `decodePispComp1BlockToWorking`, `CdngEncoder.cpp:871`, `kPispCompressMode = 1` `:599`).

Raw camera buffers: Clear HDR 8 (`kClearHdrBufferCount`), SDR 4 (`kConfiguredBufferCount`), + `mediaExtraRawBuffers` (0 on exFAT), env `APERTAR_RAW_CAMERA_BUFFERS` (`CameraController.cpp:1245-1249,1363-1371@92d0970`; `MediaProfile.hpp:150`). The copy worker may hold `buffers - 2` requests (`:8229`): 6 in Clear HDR, **2 in SDR by default**. Cached (CPU-cacheable) raw buffers for COMP1 and for Clear HDR unpacked (`:8196-8200`). Confirmed.

## 2. The chain per frame (Core)

1. Completion callback (libcamera thread): `hasCapacityForFrame` (queue < 12/24 frames) else `drop[queue-full]`; `enqueueCopy` (held ≤ buffers-2) else `drop[copy-slot]`; never copies (`CameraController.cpp:4570-4600,4759-4777,8948-8961@92d0970`). Confirmed.
2. Copy worker (1 thread, `APERTAR_RAW_COPY_WORKERS` 1..2): dma-buf sync, `memcpy(copy.size)` into a pooled `std::vector`, sync end, **release the request**, then (a) Log: `applyCdngLogFrame` in place, one 65,536-entry table lookup per sample (`LogCurve.hpp:181-186,199-213`), view depth := target bits; or (b) Clear HDR 12-bit: `compressClearHdrFrame`; then `enqueue` (`:4780-4830`). Confirmed. The LUT runs after the request is released, so it does not hold camera buffers, but it is serial on the one copy thread.
3. Writers (`dngWorkerLoop`): uncompressed `min(mediaProfile.workers, max(2, min(4, threads)))` = 4 on exFAT/ext4; lossless `min(8, threads+1)` = 5 on a Pi 5; lossy `min(4, threads)` = 4; queue 24 for compressed formats when threads ≥ 4, else the media profile's 12 (`:4116-4150`). Lossless/lossy workers `setpriority` nice 0/5 (`APERTAR_CDNG_WORKER_NICE`, `:4920-4930`). Per frame: `open(O_WRONLY|O_CREAT|O_TRUNC|O_CLOEXEC)` (no O_DIRECT), `FADV_SEQUENTIAL`, header, payload, IFD, `FADV_DONTNEED`, close (`CdngEncoder.cpp:1749-1783`); then `startWriteback(path)` per frame when enabled and `noteWrittenFile` for the 1 s fsync loop (`CameraController.cpp:4976-4979,4150-4160`). Confirmed.
4. Uncompressed payload: `writeRawPayload` packs row by row into the scratch (`writeDngRowBytes`: 16-bit memcpy; unpacked 16-bit container -> `packDng12Row`/`packDng10Row`; COMP1 -> `unpackPispCompressedRowToPacked12/10` (LUT per 8-px block, straight to packed bytes); 16-bit storage from COMP1 -> `decodePispRowToMsb16`) and `write()`s each full scratch (`CdngEncoder.cpp:1024-1062,1862-1909,918-968,1805-1859`). Confirmed.
5. Lossless payload: strips of `APERTAR_CDNG_TILE_ROWS` = 128 rows (16..1024) x full width (`:52-66,1237-1241`); per row `readJpegSamples` (COMP1: decode block then `>> (16-bits)`; unpacked: `readLe16`), `appendRow`, one `write()` per strip (`:1292-1351`). 4K: 17 strips/frame. Encoder: fixed Huffman table, predictor 1; **bits ≤ 12 uses the 4-sample LUT path (`emitDifferenceQuad`), bits 16 falls to per-sample `category()` + `emitBits`** (`src/cdng/LosslessJpegEncoder.cpp:170-178,196-212,323-338`). Confirmed. Per-job timing: `lossless timing: ... estimated_capacity_fps = workerCount x 1e6 / avg_wall_us` (`CameraController.cpp:4316-4330`). Confirmed.
6. Log plan: `planCdngLog` refuses any stream that is not unpacked 2 B/sample unless lossy (`:3807-3821`); source bits = 16 for Clear HDR 16-bit (black 3200, white 65520), target = `cdngLogStoredBits`: 16->12, 12->10, 10->8 (`include/apertar/core/Types.hpp:346-369`). Curves `kPairs` {16,12,mu 10000,F 32,foot 487}, {12,10,1500,32,200} (`LogCurve.hpp:65-69`). Confirmed. Nothing in the plan checks the compression, so **Log + Lossless JPEG in Clear HDR 16-bit is allowed** and the encoder then sees 12-bit samples (view depth 12 at `:4812`, `bitsPerSample(layout.bitDepth)` at `CdngEncoder.cpp:1303`). Confirmed (code), untested on the Pi.
7. UI/API size model `estimatedRawBytesPerSecond`: uncompressed `rawMiB x 1.06 + 0.03`, lossless `rawMiB x 0.72 + 0.15` (12-bit; 0.78 at 10, 0.82 at 8), lossy `/3 + 0.12` or `/5 + 0.10`, Log substitutes the stored bits only when `cdngLogApplied` (`src/ApertarCoreApp.cpp:5238-5281@92d0970`). Confirmed. It over-estimates uncompressed 12-bit 4K by 6 % (13.2 vs 12.44 MB) and lossless 12-bit 4K by ~50 % against the one measurement (§4 case 5).

## 4. Bytes per frame, per case (Core), with the formula

Payload = W x H x bytes/px. DNG overhead: ~1.5 KB of header/IFD (16-bit 4K DNG = 16,590,340 B, kb q1 row 26 -> 1,540 B over the payload); a LinearizationTable adds 2^bits x 2 B (8 KiB at 12 bits). Cache walks: each dma-buf sync walks the buffer once per attachment (q3 §1), 4 walks per frame in Core; no extra bytes.

### 4.1 DRAM budget per frame (extending kb q3 to these cases)

## 7. Observations that bear on the leads

- O1. Core's SDR link bytes are half cinepi-raw's (COMP1 1 B/px vs the 16-bit container), and Core's BE raw read is half; but Core pays a COMP1 LUT decode per frame and stores lossy-companded samples, while cinepi-raw stores bit-exact 12-bit (confirmed, §1, §3).
- O2. Per 16-bit uncompressed frame Core's threads move 99.5 MB (memcpy 16.59 r+w, row memcpy 16.59 r+w, `write()` 16.59 r+w) against cinepi-raw's 66.4 MB (assembly 16.59 r+w, `write()` 16.59 r+w): one avoidable pass, 33 MB/frame = 0.83 GB/s at 25 fps (confirmed from code; q3 "missed" note).
- O3. With Log, Core adds a fourth pass (LUT in place) while cinepi-raw folds the LUT into its one assembly pass (`log_lut_->encode_row` then `pack_row_12bit`, `dng_encoder.cpp:1226-1263`). Core's Log pass sits on the single copy thread (confirmed).
- O4. The 50 fps SDR loss pattern (steady single-frame gaps, 43.9 fps, queue ≤ 3, unchanged with 8 buffers) matches the kb's measured Clear HDR 30 fps mechanism (serial IPA+BE cycle > period, CFE skips one frame), not storage (probable).
- O5. Lossless encoder: 16-bit path ~275 ms per frame per worker (measured) vs the 12-bit LUT path implied ~72 ms (from "69 fps"); Log converts Clear HDR 16-bit frames to 12-bit codes before the encoder (confirmed code), so Clear HDR + Log + Lossless should be ~4x cheaper than Clear HDR lossless (probable, untested).
- O6. The pre-roll's 2 s lossless run at 60 fps (115 frames, 688 MB) proves 5.98 MB/frame for that scene and that 60 fps was delivered for 2 s; with a 24-frame queue it does not prove sustained encoder capacity (probable).
- O7. No cinemate 4K 50 fps SDR take exists in the cinemate handbook; cinemate's own dynamic resolution leaves 4K above 25 fps on SSD (confirmed absence).
