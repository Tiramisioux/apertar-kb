## Q4. How libcamera derives SensorInfo.analogCrop and ScalerCropMaximum — CONFIRMED in both forks (qbc match to the Pi binary is PROBABLE)

All three imx585 drivers register ONE pad, MEDIA_PAD_FL_SOURCE, via media_entity_pads_init(..., 1, ...) (imx585(apertar)/imx585.c:2629-2631@e5b74d3; imx585(cinemate-7modes)/imx585.c:2472-2474@bd57617; imx585(cinemate-modes)/imx585.c:4732-4734@18c1eb2), so the imx585 falls to CameraSensorLegacy (CONFIRMED by reading; the runtime class choice itself is PROBABLE since nothing was run).

Selection targets read (CameraSensorLegacy):
- At init: V4L2_SEL_TGT_CROP_BOUNDS -> pixelArraySize_ (camera_sensor_legacy.cpp:393-407); V4L2_SEL_TGT_CROP_DEFAULT -> activeArea_ (:410-416); V4L2_SEL_TGT_CROP read once as a validation (:419-423). activeArea_ is published as PixelArrayActiveAreas (:624), pixelArraySize_ as PixelArraySize (:623).
- Per configure: CameraSensorLegacy::sensorInfo() re-reads V4L2_SEL_TGT_CROP into info->analogCrop ("the crop rectangle needs to be re-read as it depends on the sensor configuration", :865-869, :878); on failure falls back to activeArea_ (:879-882); then `info->analogCrop.x -= activeArea_.x; info->analogCrop.y -= activeArea_.y` because TGT_CROP "is defined in respect to the full pixel array" while analogCrop is "relatively to the active pixel area" (:885-893). outputSize = current pad format size (:896-901).
- The ioctl: V4L2Subdevice::getSelection sets `sel.which = V4L2_SUBDEV_FORMAT_ACTIVE` and issues VIDIOC_SUBDEV_G_SELECTION on the pad (libcamera(qbc)/src/libcamera/v4l2_subdevice.cpp:1184-1190@7e9fef0).

Expected rectangle semantics (IPACameraSensorInfo::analogCrop doc): "The portion of the pixel array active area which is read-out and processed ... top-left corner is defined as the displacement from the top-left corner of the pixel array active area ... sizes define the portion of the pixel array which is read-out ... before any pixel sub-sampling method, such as pixel binning, skipping and averaging take place" (libcamera(qbc)/include/libcamera/ipa/core.mojom:160-170@7e9fef0). outputSize is the post-binning image size (:172-183). I.e. analogCrop is in NATIVE (pre-binning) pixel-array coordinates, relative to CROP_DEFAULT's origin — exactly the convention cinemate-modes' supported_modes[] comment adopts ("scaleX = analogCrop.width / outputSize.width", imx585(cinemate-modes)/imx585.c:1047-1049@18c1eb2).

ScalerCropMaximum: set to Rectangle{} at registration ("not meaningful until a camera mode has been chosen", libcamera(qbc)/src/libcamera/pipeline/rpi/common/pipeline_base.cpp:910-914@7e9fef0), then in configure(): `data->properties_.set(properties::ScalerCropMaximum, data->sensorInfo_.analogCrop)` with comment "For us, it's the same as the 'analogue crop'" (:561-568). sensorInfo_ is filled in CameraData::configureIPA via `sensor_->sensorInfo(&sensorInfo_)` (:1253-1258) and passed to ipa_->configure (:1265). The ScalerCrop control's ControlInfo is (scaleIspCrop(ispMinCropSize), analogCrop, scaleIspCrop(ispCrop)) (:598-604). scaleIspCrop(): ISP-pixel rect scaled by analogCrop.size()/outputSize and translated by analogCrop.topLeft() (:1347-1356); applyScalerCrop() does the inverse (:1390-1391) and clamps to Rectangle(outputSize) (:1402). So with analogCrop == (0,0,outputSize) every ScalerCrop is an identity mapping onto the delivered buffer — no zoom bounds information survives.

IPA consequences of a wrong analogCrop (same in both forks): IpaBase::setMode sets cropX/cropY from analogCrop.x/y (libcamera(qbc)/src/ipa/rpi/common/ipa_base.cpp:583-584@7e9fef0), scaleX/Y = analogCrop.size / outputSize (:591-592), binX/Y = min(2, int(scale)) (:602-603), noiseFactor = sqrt(binX*binY) (:606). PiSP IPA enables the BE debin block only when binX>1 || binY>1 (libcamera(qbc)/src/ipa/rpi/pisp/pisp.cpp:1128-1137@7e9fef0). ALSC uses cropX/scaleX to place the shading table (src/ipa/rpi/controller/rpi/alsc.cpp:503-523). A precedent for exactly the apertar situation is written into cam_helper_imx294.cpp: "The IMX294 driver reports analogCrop matching the output size rather than the pre-binning sensor extent, so mode.scaleX/binX always report 1.0/1" (libcamera(qbc)/src/ipa/rpi/cam_helper/cam_helper_imx294.cpp:79-81@7e9fef0).
