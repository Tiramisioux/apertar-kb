# V-H10: skeptic pass on "the linearisation chain is broken"

Hypothesis: Core assumes, without checking, that libcamera unwrapped every 12-bit buffer with the driver-default
CCMP curve. An un-armed unwrap, or GRAD_TH / GRAD_COMP_L / GRAD_COMP_H / BRIGHTNESS off their defaults, makes
Core's fixed table wrong.

Verdict: **refuted as the cause of the report on the shipped stack.** Core has no check (true, a latent gap),
but every code path that arms the unwrap holds, nothing in the stack writes the four controls, and the
"off-defaults" damage is far smaller than claimed. What is left is one log line on the Pi.

Refs: Core `01f170c`, libcamera `6b0b49f`, imx585 driver `cd548ef`. Host program:
`/home/user/build/hdr12-numeric/v_h10.cpp` (built with `g++ -std=c++20 -I/home/user/Apertar-Core/src`).

## 4. Numeric check (host, `v_h10`)

libcamera's `CcmpUnwrap::setParams` formula copied scalar; Core table from `ClearHdrCcmp.hpp` itself.

| Case | Result |
| --- | --- |
| A. Defaults | 0 of 4096 entries differ; round trip `E[C[L[c]]] == L[c]` holds for all codes. confirmed |
| B. Un-armed (buffer = code << 4) | Above black, codes 200..~700 come out 16-17x too high (e.g. code 300: 4831 vs 3298); from code ~871 up within 5 %. Matches the "flat, lifted shadows" claim |
| C. Curve off defaults (T1, T2, slope L, slope H each moved) | max error 62-66 counts of 16-bit, i.e. one step of the default table. Core re-quantises to the default code grid; values are not re-shaped |
| C. BRIGHTNESS 60 (blc 240) | black lands at 3883 while the DNG says 3200: black offset +683 |
| C. BRIGHTNESS 40 (blc 160) | values below 3200 clip to 3200 (max error 640) |

So the hypothesis's "tone errors up to thousands of codes" is **refuted**: curve drift costs at most one default
table step (~4 12-bit LSB); only BRIGHTNESS drift gives a visible black offset. Reproduce:
`/home/user/build/hdr12-numeric/v_h10`.

The un-armed case would also not be cDNG-specific: the BE renders the compressed buffer, so preview and MLV
would be flat too (the hypothesis says so). That pattern is distinguishable on the Pi at once.

## 6. Fix sketch (robustness, not a fix for the report)

Core already has the exact round-trip property (`ClearHdrCcmp.hpp:66-67`). Use it as the check, in the style
of `compressClearHdrFrame` (`CameraController.cpp:1646-1657`): one small local function, no new type.

```cpp
// True when the frame holds libcamera's CCMP expansion with the default curve: every value survives
// value -> code -> value. A buffer libcamera did not unwrap, or unwrapped with other parameters, fails.
bool clearHdrFrameMatchesTable(const uint8_t *data, size_t size, uint32_t width, uint32_t height,
                               uint32_t stride)
{
    const auto &lut = ccmp::compressionLut();
    const auto &table = ccmp::expansionTable();
    for (uint32_t y = 0; y < height; y += 64) {
        const size_t offset = static_cast<size_t>(y) * stride;
        if (offset + static_cast<size_t>(width) * 2u > size)
            break;
        const auto *row = reinterpret_cast<const uint16_t *>(data + offset);
        for (uint32_t x = 0; x < width; x += 16)
            if (table[lut[row[x]]] != row[x])
                return false;
    }
    return true;
}
```

Call it once per take on the first `mapCodes12` copy (next to `compressClearHdrFrame` at
`CameraController.cpp:5134-5135`); on false, `std::cerr` one line ("Clear HDR 12-bit: frame does not match the
CCMP table, check libcamera CcmpUnwrap") and keep the frame linear 16-bit for that take. A sampled check is
cheap; a code<<4 frame fails on its first above-black shadow pixel (table step at code 201 is not 16). A black
offset from BRIGHTNESS does not fail it; covering that needs reading BRIGHTNESS from the subdev at configure
the way `writeImx585ExtControl` opens it (`CameraController.cpp:7040`).

Host test, `tools/clear_hdr_ccmp_test.cpp` (no such test today; the `tools/*_test.cpp` list has none for
`ClearHdrCcmp.hpp`):
- defaults: libcamera formula (copied as in `v_h10.cpp`) equals `expansionTable()` for all 4096 codes;
- round trip `table[lut[v]] == v` for every libcamera output value;
- un-armed frame (`code << 4`, codes 201..700) fails `clearHdrFrameMatchesTable`;
- an armed frame passes.
