Dual Sensor Startup

How cinemate-port runs a second sensor: a second Apertar Core for cam1, started by systemd only when two sensors are found, and driven by the main Core through a relay.

main Core (cam0) second Core (cam1) systemd and the Pi not started

1. At boot: does the second Core start?

The cam1 unit is pulled in by the main unit (WantedBy=apertar-core.service). Before it starts, systemd runs a check. The check reads config.txt and sysfs only. It never opens libcamera, so it cannot disturb the sensor the main Core is running.

2. While running: how the two Cores work together

The touch UI and the WebUI only talk to the main Core. Inside it, a relay thread holds the link to the second Core. The relay does nothing until you turn on Dual sensor in the WebUI's Dual Sensor card.

  1. The relay links when Dual sensor is on and sysfs shows a sensor on both ports (or cam1's socket has answered once since the switch went on). With the switch off it reads UI.conf once a second and nothing else.
  2. Tied settings. Resolution, ISO, shutter, fps and white balance follow cam0 by default. Each can be set apart for cam1 (set_cam1_settings). Dynamic resolution runs on cam0 only.
  3. Record. record_cameras picks cam0, cam1, both or none. On record start the main Core waits up to 1 s for cam1's reply. If cam1 has been busy for 10 s, the take rolls without it.
  4. Preview. preview_source and hdmi1_source pick what the screens show, so HDMI and the WebUI follow the same choice.
  5. Restarts. The cam1 unit has no PartOf=: restarting the main Core leaves cam1 and its take alone. A restarted main Core learns about a running cam1 take before it touches the card.

What the screens say about cam1

The main Core reduces the link to one word in its state, the first that applies, in this order:

WordMeans
lostcam1 left a running take unasked, or the link dropped during one.
not_foundNo link, config.txt names a sensor on cam1, but sysfs has none.
offlineNo link.
recordingcam1 is recording.
writingcam1 still writes frames to the card.
refusedcam1 refused the last command.
standbycam1 is in standby.
busyCommands are queued or in flight.
readyLinked, idle, nothing pending.

Install once

From the Core repository folder on the Pi. A camera with one sensor can install it too; the check then skips it at every boot.

install -m 0755 scripts/start-apertar-core.sh /home/pi/start-apertar-core.sh
[[ -f /home/pi/apertar-hardware-cam1.conf ]] || install -m 0644 config/apertar-hardware-cam1.conf /home/pi/apertar-hardware-cam1.conf
mkdir -p /home/pi/.config-cam1
sudo install -m 0644 config/apertar-core-cam1.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable apertar-core-cam1

Then put a second sensor overlay in config.txt (the Boot Config card does it) and reboot. Check with systemctl status apertar-core-cam1: either "active (running)", or "condition failed" with one sensor. The journal line ApertarCore dual check: says what it found.
